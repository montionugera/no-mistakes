## Explicit run contract

Add `axi run --shipping-mode full|immutable-source` and optional `--draft` (explicit false is supported). Persist both selections before steps begin, bind them to launch identity, reject conflicting reattachment, and preserve them on recovery/rerun. Strict shipping forbids per-run/core skips, automatic publication skips, passing overrides without supported provenance, and `--yes` acceptance of unresolved actionable findings. Ordinary `--yes` behavior remains unchanged.

`full` runs every ordinary phase. Any validation commit after Review restarts validation from Review before publishing; ancestry alone cannot certify an exact current head. CI always revalidates repairs and target-comparison movement before readiness, restarting at Rebase on a full-mode target advance in this mode. A failed or parked step supplies no successful proof. The five-minute strict-mode interval applies only to periodic hosted-CI reads; native daemon health polling keeps its existing cadence.

`immutable-source` binds the existing live source branch and exact submitted SHA, including the canonical current published `dev` ref for a protected `dev` to `main` promotion. Rebase validates the live comparison without integrating the protected source; Push verifies that this exact source is already published without writing it. These are completed non-mutating implementations, not arbitrary skipped phases. All validation agents may inspect, but any source HEAD/tree/index/worktree change or fix request refuses before publication. CI cannot rebase, repair, or push the protected source. An advanced source or target requires a new run. A default-branch caller is allowed only under this explicit immutable mode; ordinary default-branch restrictions remain.

## Exact review authority

Persist a bounded review-comparison record: repository/source ref, target ref and fetched SHA, reviewed full head, merge base, SHA-256 digest of raw `git diff --no-ext-diff --no-textconv --binary --full-index <target>...<head>`, and positive monotonically increasing generation. Capture each Review candidate after fixes and before its independent review turn. Grant authority only when that exact Review completes, atomically with its completed step and approved head. A parked, failed, skipped, superseded, or incomplete coverage round cannot create authority. Invalidating/restarting Review clears successful authority and readiness. Export must verify current run head equals the approved head and the comparison generation, and reread durable authority around live forge/Git observations.

Add `axi review-receipt --run ID --phase review|ci-ready [--signing-key-stdin]`. It never starts/drives/aborts a pipeline or signs caller JSON. `review` requires completed intent/rebase/review/test/document/lint/push/pr and current exact published open PR comparison; CI may be waiting for approval. `ci-ready` additionally requires active CI with persisted readiness for that same comparison and a fresh successful applicable live check observation; optional skipped hosted lanes retain native provider semantics. Empty checks and declared no-CI are insufficient for strict Controller shipping. Completed merged runs remain inspectable through ordinary status/custody; the premerge receipt does not claim merge or release ownership. Read-only status also exposes phase readiness and comparison generation.

Bracket forge facts (source repository/ref/SHA, target repository/ref/SHA, PR identity/state/draft) and target/source Git refs with identical observations. Recompute merge base and raw diff digest from exact objects. Reject movement, missing objects, credential-bearing serialized identities, unsupported providers, stale review generation, dirty pipeline worktrees, push in flight, overrides, skips, missing required/custom steps, and unresolved actionable findings. Git authentication may use a matching configured origin but credentials never enter stored or signed proof. Initial scope is GitHub; other SCM providers return an explicit unsupported-proof error without changing their pipelines.

## Frozen signed wire

Unsigned output is the following payload. All keys are emitted in this order; all listed keys are required. IDs, refs, URL, SHAs, and digest are strings; `issued_at` and `generation` are positive integers; `draft` is boolean. Array ordering is deterministic.

```text
schema_version: 1
run_id
phase: review | ci-ready
issued_at: Unix seconds
source_repo: owner/name
source_branch
submitted_head_sha
local_head_sha
forge_head_sha
pr_url
target_branch
target_sha
merge_base_sha
diff_digest: lowercase SHA-256 hex
generation
intent_digest: lowercase SHA-256 of exact durable user intent UTF-8
shipping_mode: full | immutable-source
draft
review: {status: completed, approved_head_sha, findings_digest, findings}
steps: [{step, status: completed | running, execution: performed | verified-immutable}]
test_override: null
```

All eight pre-CI core steps and every configured custom gate must be `completed`; CI must be `running` in both premerge phases because the monitor remains active until merge. `ci-ready` changes the phase proof, never falsely marks CI completed. No pending, skipped, failed, fixing, or parked step is admissible. `review.findings` contains final durable Review findings as `{id,severity,file,line,action,description,disposition}`. `line` is a positive integer or null (native zero maps to null); severity is `error`, `warning`, or `info`. Successful strict proof permits only explicit `action: no-op` and records `disposition: non-actionable`; unresolved `auto-fix`/`ask-user`, missing, or unknown actions refuse even if an ordinary operator approval completed the step. `findings_digest` hashes the emitted findings array bytes. Historical fixed findings remain in native logs/rounds, never invented from absent final rows. `test_override` is explicitly null in the initial strict protocol; a recorded exception refuses proof and remains visible in native status. Adding exception authorization would require a new reviewed contract.

Signed output is `{schema_version:1,algorithm:"Ed25519",key_id,payload,signature}`. `key_id` is lowercase SHA-256 hex of the raw 32-byte Ed25519 public key. `payload` is standard padded base64 of the exact UTF-8 JSON payload bytes. `signature` is standard padded base64 of Ed25519 over the UTF-8 domain `no-mistakes-review-v1` followed by a NUL byte and those payload bytes. The decoded payload is at most 32 KiB; the complete envelope is at most 49 KiB. The findings digest hashes the exact emitted Go JSON array bytes, including escaping; the consumer retains that original array byte slice rather than reserializing it. Empty findings are `[]`, not `null`. The verifier authenticates bytes before parsing and rejects duplicate/unknown keys or invalid field types/values. Public-key pinning uses base64 raw32 externally. No public key inside the envelope grants trust.

`--signing-key-stdin` reads only a bounded base64 32-byte seed, derives the key and ID, and clears its byte buffers after use. It accepts no arbitrary JSON, path, environment key, or supplied key ID. The key never enters daemon IPC, agent prompts/environments, durable storage, logs, telemetry, or errors. Signing is refused from authenticated nested pipeline-agent context. Tests use deterministic non-secret fixtures only. This source work does not read or provision a real seed; that remains blocked by the activation boundary below.

## Failure and recovery

An interrupted signing export changes no pipeline state. A bad key or stale comparison yields no envelope. A target/source race cannot silently rebind a reviewed receipt. Full-mode source repairs restart Review and replace the approved generation only after successful re-review. Immutable mode cannot repair; it reports the refused mutation and leaves the protected remote untouched. A strict parked Review restored after daemon restart cannot infer a candidate generation from head alone; recovery refuses that completion and requires a fresh native rerun. Existing terminal custody rules preserve any agent-created unpublished work. No native receipt is sufficient by itself to merge, authenticate a different key, waive an override, or delete a branch.
